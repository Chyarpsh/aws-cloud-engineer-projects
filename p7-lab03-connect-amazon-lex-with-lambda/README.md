# 🔗 Connect Amazon Lex with AWS Lambda (Serverless Chatbot Backend)


# 📌 Project Overview

In this project, I integrated an Amazon Lex chatbot (BankerBot) with AWS Lambda to add real backend logic to a conversational AI application. Instead of returning static responses, the chatbot now triggers a Lambda function to dynamically generate and return a bank account balance based on user input.
This project demonstrates how conversational interfaces can be connected to serverless compute to perform real actions, making chatbots practical for production use cases such as banking, customer support, and self-service applications.


# 🏗 Architecture

User → Amazon Lex → Intent (CheckBalance) → Lambda Code Hook → Dynamic Response
Amazon Lex handles conversation flow and intent detection, while AWS Lambda executes backend logic and returns data to the chatbot.


# 🛠 AWS Services & Tools Used

| Service/Tool |	Purpose |
| ------------ | -------- |
| Amazon Lex |	Builds and manages the conversational chatbot |
| AWS Lambda |	Executes backend logic without servers |
| AWS IAM |	Grants permissions for Lex to invoke Lambda |
| Amazon CloudWatch	Logs | Lambda execution and debugging data |
| Python	| Implements backend logic in Lambda |


# 🔧 What I Built

I enhanced BankerBot by:

    Creating a Lambda function that generates a random bank balance
    
    Connecting the function to Amazon Lex using a bot alias
    
    Configuring code hooks so the Lambda function runs when the CheckBalance intent is fulfilled
    
    Returning dynamic, personalized responses to users instead of static text

As a result, the chatbot now responds with real-time data generated by Lambda, making the interaction more realistic and engaging.


# ⚙️ Key Implementation Steps

1. Lambda Backend Logic

I created a Python-based AWS Lambda function that:

    Generates a random dollar amount to simulate an account balance
    
    Formats the response in a structure Amazon Lex understands
    
    Returns the balance to the chatbot for display to the user 

This demonstrates how Lambda can act as a backend service for conversational applications.

2. Connecting Lambda via Bot Alias

I connected the Lambda function to BankerBot using a Lex bot alias (TestBotAlias).
An alias acts as a stable pointer to a specific version of a bot and ensures Lex can safely invoke Lambda during testing before production deployment 

3. Using Code Hooks

Even after connecting Lambda to the bot alias, I had to configure code hooks at the intent level.

I enabled a code hook for the CheckBalance intent so that:

    Lex knows which intent should trigger Lambda
    
    Lambda runs at the fulfillment stage of the conversation

Without code hooks, Lex would not automatically execute the backend logic 

4. Testing the End-to-End Flow

After configuration, I tested the chatbot by:

    Asking for an account balance
    
    Providing the required slot values (account type and date of birth)
    
    Verifying that Lex successfully invoked Lambda
    
    Confirming the chatbot returned a dynamic balance

This validated the full Lex → Lambda → Lex integration.

5. Customizing the Lambda Response

To improve user experience, I enhanced the Lambda code to:

    Randomly select descriptive phrases
    
    Dynamically insert the user’s account type
    
    Format the balance in a natural, conversational way

This made the chatbot feel more human-like and interactive, rather than robotic
